# Sindbad Torino

صفحة واحدة بـ HTML5 وTailwind CSS وJavaScript. الإيطالي هو اللغة الافتراضية، والعربي متاح من اختيار اللغة. أسماء الأطباق بالإيطالي والعربي، والمكونات المتاحة من المنيو الأصلي بالإيطالي.

## التشغيل المحلي

يتطلب Node.js 24. من مجلد المشروع شغّل الأوامر التالية ثم افتح الرابط المطبوع في الطرفية.

```sh
npm ci
npm run build:css
npm run dev
```

التشغيل المحلي يستخدم SQLite في الذاكرة. لتخزين بيانات الاختبار بين مرات التشغيل، اضبط `SINDBAD_DB` على مسار ملف محلي. إعدادات الطاولات المحلية افتراضية لأغراض الاختبار. أمر `npm run build` يجهز نسخة النشر.

## المنيو والطلبات

- `public/index.html` هيكل الصفحة. `styles/site.css` مصدر Tailwind. `public/menu-data.js` بيانات الأصناف، و`public/menu.js` التبويبات والبحث والسلة. صور الأصناف مستخرجة من المنيو ومربوطة بالمعرّف في بيانات الصنف. رسمة الفرن توضيحية لكارت الكالزوني، وصورة الغلاف تعبيرية عن الأجواء.
- المنيو الأصلي لا يعرض أسعارًا. القيم في `priceCents` أسعار توصيل استرشادية للأصناف المطابقة من [Deliveroo Via Milano](https://deliveroo.it/it/menu/torino/torino-centro/sindbad-kebab-torino). اضبطها بعد اعتماد أسعار المطعم. خلو الحقل يعني أن السعر يتأكد مع المطعم.
- السلة قائمة مساعدة للطلب بالتليفون. منصات التوصيل تدير اختيار الأطباق والدفع على صفحاتها.

## الطاولات والحجوزات

1. اضبط `RESTAURANT_TABLES` في إعدادات بيئة الموقع على JSON يربط أرقام الطاولات الفعلية بعدد المقاعد. مثال للتوضيح فقط `{"1":2,"7":4,"12":6}`.
2. `RESERVATION_MINUTES` يحدد مدة الحجز من 30 إلى 240 دقيقة. القيمة الافتراضية 90 دقيقة. الموقع يعرض أرقام الطاولات حسب العدد والموعد. عند الإرسال، تتحقق قاعدة البيانات مجددًا من التداخل وتمنع طلبين متزامنين لنفس الطاولة.
3. افتح `/admin` لمراجعة الطلبات المعلقة والتأكيد أو الرفض بعد التواصل مع الضيف. الرفض يحرر الطاولة. تُحفظ طلبات الحجز في D1 بتوقيت تورينو. الحجوزات الأقدم تبقى محفوظة حتى لو لم يُسجل لها رقم طاولة.
4. الإدارة على النسخة الخاصة تتطلب صلاحية المالك وإعداد `OWNER_PRIVATE_ADMIN=1` أو هوية الموظف في `ADMIN_USER_ID`. اضبط هوية المدير صراحةً قبل إتاحة الموقع للجمهور.

## نادي أصدقاء سندباد

1. النموذج يرسل الاسم الكامل، الهاتف الدولي، الإيميل، يوم وشهر الميلاد والموافقة إلى `POST /api/birthday`. يسجل D1 البيانات، ثم يرسل رابط تأكيد. العرض يُرسل للمشترك المؤكد فقط، مع رابط إلغاء الاشتراك وكود صالح يوم الميلاد. يتحقق الموظف من الكود ويسجل استخدامه من `/admin`.
2. اختر قناة إرسال واحدة على الأقل واضبط بياناتها في إعدادات بيئة الموقع. الإيميل له الأولوية لو القناتان متاحتان. مفاتيح المزوّد تظل في الإعدادات السرية.
   - الإيميل عبر Resend باستخدام `RESEND_API_KEY` و`EMAIL_FROM` من عنوان مرسِل معتمد.
   - الرسائل عبر Twilio باستخدام `TWILIO_ACCOUNT_SID` و`TWILIO_AUTH_TOKEN` و`TWILIO_FROM`.
3. اضبط نفس القيمة السرية `BIRTHDAY_JOB_SECRET` على الموقع وعلى مشغّل الجدولة. عيّن `SINDBAD_SITE_URL` إلى رابط الموقع، وأضف `SINDBAD_SITE_SERVICE_TOKEN` للمشغّل عند توافر رمز وصول خدمة للنسخة الخاصة. شغّل الأمر التالي يوميًا، مثلًا الساعة 09:00 بتوقيت `Europe/Rome`، من مجدول موثوق.

   ```sh
   npm run birthday:run
   ```

4. السكربت ينادي `POST /api/birthday-run` بتفويض خادمي. المهمة تقارن اليوم والشهر بتوقيت تورينو. جدول القسائم يضمن كودًا واحدًا لكل مشترك في نفس التاريخ. عند رفض المزوّد الطلب يمكن إعادة المحاولة في نفس اليوم. لو نتيجة الإرسال غير مؤكدة بعد انقطاع الشبكة، راجع سجل المزوّد قبل إعادة إرسال الرسالة لتفادي التكرار.

`drizzle/0000_sindbad.sql` و`drizzle/0001_tables_and_club.sql` هما مخطط قاعدة البيانات وترقيته. `worker/index.js` يحتوي على منطق الخادم.

## التوصيل وطرق الدفع

- قسم `#delivery` في `public/index.html` فيه روابط Glovo وDeliveroo وJust Eat ورقم الطلب بالتليفون. غيّر الروابط من نفس الملف.
- طرق الدفع (كاش، كروت، دفع أونلاين على التطبيقات) عناصر `.pay-list` في نفس القسم. عدّلها حسب اللي المطعم بيقبله فعلًا، ونصوصها في `public/languages.js` تحت `deliveryCopy`.
- تنسيق الكروت والتوصيل في `styles/extras.css`، وهو مستورد في `styles/site.css` ومنسوخ في `public/styles.css`، فالموقع يشتغل بدون إعادة بناء. بعد أي تعديل شغّل `npm run build:css`.
- صور الأطباق في `public/assets/dishes/` اتكبّرت ضعفين وتنضّفت حوافها. الأفضل استبدالها بصور أصلية عالية الدقة لما تتوفر.
